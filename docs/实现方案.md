# 万象同纹：详细实现方案

版本：0.1｜2026-11-08｜本地交互作品

当前实施更新：0.2版已完成全部4312条官方元数据接入与五组联动可视化，当前文档下方为第一版历史方案。最新详细方案见[可视化组件设计](可视化组件设计.md)，运行与数据契约见README.md。材料、工艺与年代清洗规则在scripts/import_official.py，审计见data/normalized-audit.json。

数据获取更新（同日）：官方完整元数据表已提取并通过RAR文件CRC32和XLSX内部ZIP校验，包含4312条有效记录；图片全集尚未取得。下文“下载失败／未取得”描述为第一版开发时状态；当前网页仍是10件精选样本，尚未进行全集映射。具体审计见data/official-audit.json和docs/官方数据获取.md。

## 1. 目标和边界

围绕器物上的纹样、材料和技法，建立“浏览全景 → 筛选对象 → 并排比较 → 阅读案例 → 追溯来源 → 我的策展”的闭环。第一版使用真实、精选的The Met公开记录；不声称覆盖ChinaVis官方4312条数据。官方数据包当前下载失败，后续通过标准模型导入。

不以样本分布推断历史生产量，不以视觉相似推断传播。跨文化案例仅采用博物馆明确解读。所有中文标题为本项目译名，纹样标签为编辑标注。

## 2. 技术决策

本地环境已具备Node和Python。第一版采用原生ES Modules、语义化HTML、CSS和SVG，免第三方依赖；数据量目前很小，无需框架、后台和数据库。相较前期候选React方案，此实现便于离线演示、复现与直接查看源码。图表均由数据计算，无截图冒充交互。后续达到数千条时按需引入Canvas或框架。

Node静态服务仅绑定127.0.0.1。浏览器通过同源fetch加载本地JSON和图片。所有外部链接为来源引用，核心流程不依赖外网。数据来源网页和API发生冲突时同时记录，不静默修改。

## 3. 文件和模块

- index.html：主导航、展览首屏、探索区、故事区、对话框和策展栏。
- styles.css：色彩、排版、响应布局、交互状态和减弱动效。
- app.js：页面状态、事件、SVG视图、详情、比较、策展及导出。
- lib.js：纯函数，负责筛选、区间相交、标签统计、CSV与URL状态。
- data/collection.json：经审核的统一记录。
- data/raw/：API原始记录，保留源字段。
- assets/objects/：已确认Public Domain的本地图像。
- scripts/：采集、标准化、审计、静态服务。
- tests/：统计逻辑和数据一致性检查。

## 4. 七步落地

1. 下载：按馆藏ID获取官方API JSON；仅下载明确Public Domain的图像，保存来源和采集时间。
2. 理解：审计身份、年代、生产地区、材料、图像可用性；收藏地和生产地独立。API年代边界与页面展示文字可能有不同精度，详情同时说明。
3. 过滤：保留缺图记录，缺图显示文字占位。当前为目的性精选样本，不具代表性。筛选仅改变当前子集，不修改底稿。
4. 处理：稳定ID、原始文本、编辑译名、多值标签、起止年代、来源链接分开保存；每条标签明确编辑属性。
5. 映射：横向区间时间线映射API起止年；地区条图编码藏品数；纹样×生产地区矩阵编码具有标签的藏品数；图谱卡片提供图像细读。
6. 美化：暖白、靛蓝、朱砂；宋体标题、无衬线正文；用真实文物构成封面，背景纹样仅为抽象装饰，不作为文物复原。
7. 交互：多条件相交筛选、矩阵点击、时间筛选、清除、详情、2—4件比较、图片放大、策展本地保存、JSON策展与CSV子集导出、URL分享筛选。

## 5. 数据契约

每条记录包含id、accession、title、originalTitle、dateLabel、start、end、region、place、material、technique、motifs、source、apiSource、image、rights、summary、annotation、retrievedAt。id用met-前缀。region指生产或文化归属，细节见place；收藏机构固定The Met。缺失图片image=null；缺失时间应保留null而非猜测（第一版记录均有边界）。纹样允许多选，所以标签合计可能超过藏品总数。

故事使用独立文本及来源，与时间线区间不建立虚假的单件传播边。个案解释只针对被引用的器物；其他相似器物为比较对象，不认定为原型。

## 6. 状态与交互协议

状态包括q、region、material、motif、from、to、sort、view、comparisonIds和savedIds。筛选取交集，时间采用闭区间相交(start <= to && end >= from)。所有视图使用同一个filtered集合。地区条形可取消筛选；矩阵单元格设置纹样和地区；清除仅重置筛选，保留策展。

URL存储筛选，localStorage存储策展ID；分享不自动泄露策展内容。对localStorage禁用、无结果、单件比较、超过四件、图片缺失、数据读取失败都有可见提示。用户输入进入DOM前转义。对话框使用原生dialog，Escape关闭、恢复焦点。

## 7. 开发顺序与验收

A. 数据采集和契约：真实JSON、本地图像、审计报告，无孤立图像引用。
B. 视觉骨架：桌面和移动端布局、首屏、导航、来源说明。
C. 探索闭环：筛选、SVG图表、列表、详情与比较。
D. 故事与策展：可追溯案例、收藏持久化、导出、URL状态。
E. 验证：Node测试覆盖区间边界、组合筛选、多标签计数、CSV转义、数据完整性；HTTP检查资源可达；浏览器验证实际筛选、比较、详情、窄屏及控制台。

质量目标：普通观众能独立完成“选择纹样→打开对象→比较→查看来源”；筛选结果和图表总数一致；缺失值透明；键盘可操作；本地断网可展示已取得图片。性能500ms仅为目标，未经测量不作为结论。

## 8. 后续扩展与当前限制

接入赛事全集时先映射数据，不直接拼接：建立机构命名空间和去重规则，输出字段完整率，人工审核中文翻译。扩展精标样本后再增加跨机构筛选、比例比较、更多故事、海报与汇报视频。当前不具备正式参赛研究规模，不生成未经验证的统计洞察。
